# AZB-Glossar — Design

Date: 2026-09-28

## Purpose

A shared glossary for one Microsoft Teams group chat. Members open it from a
tab in the chat header. They see every term in one overview and
click a term to read its explanation. Any member can add or correct terms.

Self-hosted on the owner's Proxmox homelab as a Docker container, exposed
through the Pangolin reverse proxy as a public resource with no authentication.
Docker is not available on the development machine, so the container is only
built and run on the homelab. The server logic is tested locally without Docker.

## Success criteria

- Opens and renders inside a chat tab of a small custom Teams app (desktop and mobile).
- First paint is fast: one small HTML file, no external requests, no framework.
- Plain, always-dark page. On a wide desktop tab it uses the full width.
- Terms persist across container restarts and are shared by everyone in the chat.
- A stranger or a typo cannot wipe the glossary.

## Non-goals

Accounts or sign-in, per-user attribution, categories or tags, rich text or
Markdown, version history, real-time push updates, multiple glossaries, search
ranking, import/export UI, and the Teams JS SDK.

## Architecture

One container: `node:alpine` running `server.js` with **no npm dependencies**.

```
server.js          entrypoint: reads config, starts the server, graceful shutdown
src/config.js      environment parsing and validation
src/store.js       terms: validation, atomic persistence, backups
src/rate-limit.js  per-client sliding-window limiter
src/app.js         HTTP routing, security headers, caching
public/index.html  the whole UI, inline CSS + JS, no external requests
test/              node:test suites: store, api, config, and browser e2e
Dockerfile
docker-compose.yml
.env.example
README.md          deploy, Pangolin settings, Teams checklist
```

Data lives in `$DATA_DIR/glossary.json` (default `/data`), a mounted volume.
Format: `{ "version": 1, "terms": [ { id, term, definition, createdAt, updatedAt } ] }`.

- The file is loaded into memory at startup. Writes go through a single
  serialised queue and are atomic: write `glossary.json.tmp`, then rename.
- Once per day (on the first write after midnight UTC) the previous file is
  copied to `$DATA_DIR/backups/glossary-YYYY-MM-DD.json`. The last 14 backups
  are kept.
- If the file is missing it is created empty. If it is corrupt the server
  refuses to start and logs why. It never silently overwrites it.
- `id` is a random 8-character string generated by the server.

## API

All bodies are JSON. Errors are `{ "error": "<message>" }`.

| Method and path | Purpose | Notes |
|---|---|---|
| `GET /api/terms` | List all terms | gzip, `ETag`, `Cache-Control: no-cache`, 304 supported |
| `POST /api/terms` | Add a term | 201 with the created term |
| `PUT /api/terms/:id` | Edit term and/or explanation | 200 with the updated term |
| `DELETE /api/terms/:id` | Delete a term | needs `X-Admin-Key`, 204 |
| `GET /healthz` | Container health check | 200 `ok` |

Validation and limits:

- `term`: trimmed, 1–100 characters. `definition`: trimmed, 1–5000 characters.
- Duplicate terms are rejected with 409, compared ignoring case and accents.
- Request body max 16 KB (413). Total terms max 5000 (409 with a clear message).
- Writes (including failed delete attempts) are rate-limited to 30 per minute
  per client IP (429). The client IP is the **last** `X-Forwarded-For` entry,
  because the server always sits behind Pangolin and earlier entries can be
  forged by the client.
- `DELETE` compares `X-Admin-Key` with `ADMIN_KEY` using a timing-safe compare.
  Wrong or missing key gives 403. If `ADMIN_KEY` is unset, delete is disabled
  (403) and a warning is logged at startup.
- Concurrent edits: last save wins.

## Page

- Fixed dark theme, `color-scheme: dark`, system font stack, no animations,
  no images. Body text stays comfortably readable (about 16 px).
- **Header row:** the title and the **+ Add term** button on the left, the term
  count and a filter box (instant, matches term and explanation) pushed to the
  right. On a phone-width tab the title and count are hidden so the button and
  the filter share one row.
- **Overview:** one alphabetical list of all terms (locale-aware sort) with
  small letter dividers. Terms starting with a non-letter go under `#`.
- **Uses the full width on desktop:** the list is laid out in CSS columns
  (`column-width` about 22rem) separated by thin vertical divider lines
  (`column-rule`). The number of columns follows the tab width: 1 on a narrow
  or mobile tab, 4 or more on a wide monitor. Terms read top to bottom within
  a column, then continue in the next column. A letter divider is never left
  alone at the bottom of a column. The page itself never scrolls horizontally.
- **Reading a term:** each term is a `<button>` (`aria-expanded`). Clicking it
  expands the explanation directly below it, inside the same column. Clicking
  again collapses it. More than one term can be open at once. Because columns
  reflow when a term expands, the clicked term is kept in view.
- **Always clean:** a fresh load starts fully folded. After adding or editing a
  term everything is folded (nothing stays open), and the added or changed term
  is scrolled into view and highlighted for about 2.5 seconds. When the page is
  shown again (tab visible again, or restored from the browser's back/forward
  cache) everything is folded again. Text the user has typed but not saved is
  never discarded: a form with changes stays open, an untouched form is closed.
- **Explanations** are plain text with line breaks preserved. All user text is
  inserted with `textContent`, never as HTML.
- **Add / edit:** an inline form panel (term and explanation), not a modal.
  Editing is reached from an **Edit** link inside the expanded term.
- **Delete:** inside the edit form. A **Delete** button reveals an inline
  admin-key field and a confirm button. A wrong key shows an inline message.
  The key is only held in memory for that request.
- **Freshness:** the list is fetched on load and again when the tab regains
  focus (at most every 5 seconds), so terms added by others appear. A form
  that is being edited is kept when the list refreshes.
- **Errors and empty state:** if the server cannot be reached the page shows a
  clear message with a Retry button. With no terms yet, it shows a short hint
  to add the first one. Save failures keep the form open with the text intact.

## Teams compatibility

- **Correction (2026-09-28):** the first version of this design assumed the
  built-in Teams **Website** tab would show the page. It does not: since July
  2024 new Teams opens a Website tab's URL in a new browser tab, regardless of
  the site's headers (Microsoft 365 Developer Blog, "Upcoming updates to loading
  websites in Teams tabs"). Embedding needs a Teams app.
- The page is wrapped in a small Teams app package (`teams-app/`, built by
  `scripts/build-teams-app.js`): a manifest with one static tab (scopes
  `personal` and `groupChat`) pointing at the public URL, plus a 192x192 color
  icon and a 32x32 white-on-transparent outline icon. The manifest keeps a
  fixed app id so re-uploads update the same app.
- Inside a frame (or the Teams mobile webview) the page loads the Teams JS SDK,
  vendored in `public/vendor/` and served from the same origin, calls
  `app.initialize()` and, once the list has loaded, `notifyAppLoaded()` and
  `notifySuccess()`. Outside a frame the SDK is never fetched.
- Response header `Content-Security-Policy: frame-ancestors 'self' <teams
  origins>` and **no** `X-Frame-Options`. The Teams origin list is configurable
  through `FRAME_ANCESTORS`. The default is verified against Microsoft's current
  documentation during implementation.
- Also sent: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
  and a CSP limiting `connect-src` to `'self'`. Scripts are inline or from our
  own origin (the vendored SDK), styles are inline, so the CSP allows `'self'`
  and `'unsafe-inline'` for them. This is acceptable because no user text is
  ever inserted as HTML.
- No cookies. No dependence on localStorage or sessionStorage (Teams iframes
  partition storage). No `alert`, `confirm`, `prompt` or popups. No external
  fonts, scripts or images.
- Responsive down to a phone-width Teams tab.

## Configuration (environment)

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | `8080` | Listen port |
| `DATA_DIR` | `/data` | Data and backup location (mounted volume) |
| `ADMIN_KEY` | *(unset)* | Secret required to delete terms |
| `FRAME_ANCESTORS` | Teams origins | Origins allowed to embed the page |

## Deployment

- `docker-compose.yml`: one service, the volume mounted at `/data`,
  `restart: unless-stopped`, a `HEALTHCHECK` on `/healthz`, and env from `.env`.
- The container runs as a non-root user.
- README covers: Pangolin resource settings (public resource, SSO off, no
  header rewriting that adds `X-Frame-Options`), a `curl -I` check for
  frame-blocking headers, and a short Teams verification checklist.

## Error handling summary

- Malformed JSON or invalid fields: 400 with a specific message.
- Unknown id: 404. Duplicate term: 409. Body too large: 413. Rate limited: 429.
- Storage write failure: 500, in-memory state is not changed, and the error is
  logged. The UI keeps the user's input. Renaming the temp file over the data
  file is retried briefly on `EPERM`/`EBUSY`/`EACCES` (antivirus, SMB/NFS
  volumes).
- Keep-alive is 65 s, longer than typical proxy idle timeouts, to avoid
  sporadic 502s from connection reuse behind Pangolin/Traefik.

## Testing

Automated (`node --test`, run locally, no Docker):

- add, edit and list; alphabetical data round-trips; whitespace is trimmed
- duplicate rejected (case and accent insensitive); length and count limits
- delete needs the admin key; wrong key, missing key, and unset `ADMIN_KEY`
- data survives a server restart; corrupt file stops startup
- rate limit; oversized body; ETag/304
- response headers: `frame-ancestors` present, no `X-Frame-Options`
- transient rename failures are retried; persistent ones leave memory unchanged
- real page in headless Chrome/Edge over the DevTools protocol: column count at
  1600, 1000, 400 and 320 px, no horizontal scroll, expand/collapse, filter,
  add, duplicate, edit, delete with admin key, and user text never executed
  as HTML

Manual, once deployed: upload the Teams app package, add it to a group chat, open the tab on desktop and mobile, check
the multi-column layout at several widths, add, edit and delete a term, and
restart the container to confirm persistence.

## Risks

- **No authentication:** anyone who finds the URL can add or edit terms. This is
  mitigated by limits, rate limiting, daily backups, and the admin key on delete.
  A random subdomain is a free extra precaution.
- **Pangolin or another proxy adding `X-Frame-Options`** would make Teams refuse
  to show the page. The README includes a check.
- **Column reflow:** expanding a term in a multi-column layout can move later
  terms into a different column. The clicked term is scrolled into view to keep
  this from being disorienting. If it still feels wrong in use, the fallback is
  a fixed side panel for the explanation.
